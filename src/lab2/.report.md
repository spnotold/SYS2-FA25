2）分析 forward 和 stall 两种技术各自的优缺点（从 CPI、时钟频率、元器件开销等角度）。

- Forward（数据前递）
  - 优点：显著降低 CPI（大多数算术类 RAW 通过 EX/MEM、MEM/WB 前递即可消除停顿）。本次我支持 EX→ID、EX/MEM→ID、MEM/WB→ID，优先级 EX > EX/MEM > MEM/WB，能覆盖大部分依赖链。
  - 代价：
    - 组合比较与多路选择器增加（ForwardUnit 的比较、Core 里两路 3:1 选择），拉长 ID 段的组合路径；
    - 需要更仔细的旁路选择编码与异常场景处理（尤其 Load 不能当拍 EX 前递）。
  - 频率影响：ID 段的比较+Mux 可能会成为临界路径的一部分，但整体仍然划算，因为减少了大量气泡。
- Stall（停顿/插泡）
  - 优点：电路简单可靠（HazardDetect 只负责发 `if_stall` 和 `bubble_idex`），对复杂或不可前递（如 load-use，或跨更长距离的依赖）场景兜底；对控制流也能配合 flush 保证正确性。
  - 代价：
    - CPI 增大，尤其是真实内存模型下读写有延迟时，结构竞争+load-use 叠加带来明显停顿；
    - 还要和总线握手、结构竞争打配合（IF/MEM 的 `if_stall`/`mem_stall`）。
  - 频率影响：性能上更吃亏。

实际：尽量“能前递就前递，前递不了再 stall”。这也是我实现的策略。

3）对数据竞争、控制竞争、结构竞争进行归纳分类；目前 CPU 可能碰到哪些？

- 数据竞争（RAW 为主）
  - 典型：
    - 算术连续依赖：EX/MEM 的 `rd` 被下一条/下下条作为 `rs1/rs2` 使用；
    - load-use：EX 是 Load，下一条在 ID 就要用该 `rd`；
  - 我现在的处理：
    - 前递：EX→ID、EX/MEM→ID、MEM/WB→ID；
    - stall：HazardDetect 对“EX 为 Load 命中 ID 源”的场景发 `if_stall`+`bubble_idex`；
- 控制竞争
  - 典型：分支（BEQ 等）、JAL、JALR。
  - 我现在的处理：EX 判定是否重定向，Core 在当拍清空 ID/EX（气泡）并对 IF/ID 做两拍覆盖式 flush（防止错路径回复在 T 或 T+1 任一拍写入）。
- 结构竞争
  - 典型：指令取值与数据访存共享同一物理内存端口，IF 与 MEM 无法并发。
  - 我现在的处理：IFMEMFSM 做了 `S_IF1/IF2` 与 `S_WAITFOR1/2→S_MEM1/2` 的时序编排，期间发 `if_stall`、`mem_stall` 让前端/中段停住，并在 MEM2 末释放。

本 CPU 目前会遇到以上三类都存在：数据（算术 RAW、load-use）、控制（分支/跳转）、结构（IF/MEM 抢端口）。

4）如果数据竞争和控制竞争同时发生应该如何处理？

- 策略上我优先“控制正确性”：一旦 EX 判定分支/跳转采纳，先对错路径做 flush（Core.sv 里 `flush_ifid` 优先级最高），确保后续看到的都是气泡；
- 同时，如果此时还存在 load-use（比如分支比较依赖刚从内存读的值），HazardDetect 仍会发 `bubble_idex`，这样 EX 当拍进入的是气泡，不会把错误的源值推进；
- 对结构竞争同时发生的情况（IF 正在握手、MEM 又要访存），IFMEMFSM 把 “先完成一次取指，再去服务数据访存” 写成了 WAITFOR1/2→MEM1/2 的路径，并在这些态下拉高 `mem_stall` 冻结中间级，同时 flush MEMWB 避免错提交；

5）对总线（mem_ift/AXI）引入的好处与坏处（开发、内存访问、外设、调试）。

- 好处：
  - 更贴近真实 SoC：ready/valid 握手、不可一拍返回，逼着我把流水、停顿、前递设计得更严谨；
  - 易扩展外设：AXI-Lite 统一协议，MMIO 外设（UART、Conv、Misc）接入更自然；
  - 代码组织清晰：把“协议转换”（Mem2Axi.sv）、“IF/MEM 仲裁”（IFMEMFSM.sv）解耦成独立模块，调试边界更明确；
- 坏处：
  - 复杂度上升：IF 和 MEM 不能并行，需要状态机调度，`if_stall/mem_stall` 交互也要考虑优先级；
  - 调试成本：ready/valid的握手有点复杂，需要看大量波形；
  - 性能损失：单端口物理内存引入结构冲突，CPI 变差，需要更多前递/更激进的预测才能补回来（本实验没做预测）。

- 我这次实现的关键点：
  - ForwardUnit：编码 00(RegFile)/10(EXMEM非Load)/01(MEMWB)
  - HazardDetect：只对真正读取寄存器的指令比较，命中 EX 为 Load 则 `if_stall=1` 且 `bubble_idex=1`；
  - IFMEMFSM：参照文档状态机，提前/持续拉高 `mem_stall` 保住 EX 发起的访存请求，MEM2 尾声释放，同时我在 Core 里加了回填 IF/ID 的小缓存，避免 `mem_stall` 释放当拍丢指令。
